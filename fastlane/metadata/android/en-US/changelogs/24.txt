Fixes "Z.ai auth probe never returns a result on a real Android WebView". Your Diagnostics showed it exactly: login actually succeeded (the token and oauth_id_token cookies exist), but every check read outcome=probe-error, error="probe did not return a readable result", so the card stayed on "Not signed in" and the sign-in sheet never closed itself. Root cause: the probe script returned a JavaScript Promise to WebView.evaluateJavascript, which on a real Android WebView cannot await it - it hands back "{}" instead of the result (headless-browser tests awaited the Promise, which is why tests passed while the phone never worked). The probe now stores its result on the page and the app polls it with short synchronous reads (with a timeout budget that reports the real reason instead of a generic error). Applied everywhere the probe runs: the hidden engine's connection check, the sign-in sheet's 2-second session poll, the X-close final probe and the page-finished fast path - so after login the sheet closes itself and the card shows Connected. Also adds a source-level guard test that fails if any script handed to evaluateJavascript ever returns a Promise again, plus on-device verification steps in docs/zai-auth-probe-verification.md. Same signing key - installs over v1.0.22 with one tap.
