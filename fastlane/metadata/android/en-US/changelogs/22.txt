Fixes the "logged in but the card says Not signed in" loop reported on v1.0.20. Root cause: chat.z.ai keeps your session token in its own browser storage (localStorage) and authorizes API calls with a Bearer header, while the app only checked the session cookie - and the server answers a cookie-less check by silently minting a fresh guest, so the app kept reporting "Not signed in" even right after a successful Google login. The session check now mirrors exactly what the chat.z.ai site itself does (Bearer token from the page's own storage plus the cookie fallback), for both the sign-in sheet and the hidden browser. Also new: a Diagnostics section on the Z.ai tab (collapsed by default, one-tap copyable, contains no secrets) showing the last check result and which branch fired, both browsers' last URLs and user agents, cookie names (never values), whether the session survived an app restart, and an orange warning if the sign-in sheet and the hidden browser ever disagree. Session cookies chat.z.ai sets are session-scoped (server-verified); the fix no longer depends on them. Same signing key - installs over v1.0.20 with one tap.
